생성 패턴이란?

소프트웨어 디자인 패턴은 자주 나타나는 문제를 해결하는 재사용 가능한 해결책입니다. 그 중 생성(Creational) 패턴은 객체를 어떻게 생성하고 관리할지에 초점을 맞춘 패턴 유형입니다.

생성 패턴은 객체를 만드는 방법을 똑똑하게 설계함으로써, 무분별한 new 사용이 가져올 수 있는 복잡함이나 문제를 줄여줍니다.

왜 필요할까요?

  • 프로그램 곳곳에서 직접 객체를 생성하면 코드 수정이 어렵습니다
  • 실수가 생길 가능성이 높아집니다
  • 객체 생성 과정을 한 곳에서 제어하여 유연성과 유지보수성을 높입니다

🏭 Factory Method 패턴

객체 생성을 전담하는 '공장' 역할의 메서드를 두어 객체를 만들어내는 방식을 캡슐화하는 패턴입니다.

🎂

케이크 가게 비유

생일 케이크가 필요할 때, 직접 밀가루와 설탕을 사다가 케이크를 만들 수도 있지만, 케이크 전문점(공장)에 주문해서 완성된 케이크를 받을 수도 있습니다.

가게에 주문하면 우리는 케이크를 만드는 복잡한 과정을 알 필요 없이 결과물만 얻을 수 있습니다!

해결하는 문제

  • 객체 생성 코드를 한 곳으로 모아 관리
  • 새로운 종류의 객체 추가 시 한 곳만 수정
  • 중복 코드 감소
  • 변경에 쉽게 대응

☀️ Singleton 패턴

오직 하나의 객체만 생성되도록 보장하는 디자인 패턴입니다. 어떤 클래스의 인스턴스를 프로그램 전체에서 단 하나만 유지하고, 모두 그 하나를 공유해서 사용합니다.

☀️

태양 비유

태양은 하나이기에 지구상의 모든 생물이 그 하나의 태양을 공유합니다. 코드에서 태양 객체를 싱글톤으로 만든다면, 어떤 클래스에서 태양을 부르든 항상 똑같은 태양 객체를 받게 됩니다.

🏫

교장선생님 비유

한 학교에는 보통 교장선생님은 한 분만 계십니다. 여러 명의 교장선생님이 있으면 지시가 서로 달라 혼란스럽겠죠. 그래서 학교 규칙상 딱 한 사람만 교장이 되며, 모두가 그분의 결정을 따릅니다.

해결하는 문제

  • 공통 자원을 하나로 관리
  • 설정 충돌 방지
  • 데이터 일관성 유지
  • 메모리 자원 절약

class Sun: _instance = None # 유일한 인스턴스 저장 def __new__(cls): # 이미 존재하는지 확인 if cls._instance is None: cls._instance = super(Sun, cls).__new__(cls) return cls._instance # 사용 예시 sun1 = Sun() sun2 = Sun() print(sun1 is sun2) # True - 같은 객체!

⚖️ Factory Method vs Singleton

두 패턴 모두 생성 패턴이지만, 해결하는 문제와 방식이 다릅니다.

공통점

  • 둘 다 객체 생성과 관련된 패턴
  • 코드를 더 효율적이고 깔끔하게 만들기 위한 목적
  • 필요한 상황에서만 적절히 사용해야 함

차이점

구분 Factory Method Singleton
초점 어떻게 만들지 몇 개 만들지 (하나만)
목적 객체 생성 방식의 유연성 유일한 인스턴스 보장
객체 수 여러 개 생성 가능 단 하나만 생성
사용 예 다양한 종류의 객체 생성
(장난감, 문서, UI 컴포넌트)		 공유 자원 관리
(설정, 로그, 데이터베이스 연결)
핵심 장점 확장성, 코드 중복 감소 일관성, 자원 절약

🎯 요약

Factory Method가 "어떻게 만들지"에 대한 패턴이라면,

Singleton은 "몇 개 만들지(하나만)"에 대한 패턴입니다.

둘 다 사용 목적이 다르므로 상호 대체되는 것은 아니며, 상황에 따라 각각 단독으로 또는 함께 사용할 수도 있습니다!

언제 무엇을 사용할까?

Factory Method를 사용하세요

  • 여러 종류의 객체를 만들어야 할 때
  • 객체 생성 로직이 복잡할 때
  • 새로운 타입 추가가 예상될 때
  • 생성 과정을 숨기고 싶을 때

Singleton을 사용하세요

  • 전역에서 하나만 필요할 때
  • 공유 자원을 관리할 때
  • 상태를 일관되게 유지해야 할 때
  • 자원 낭비를 막고 싶을 때
