디자인 패턴 배우기

Factory Method 패턴과 Singleton 패턴을 쉽고 재미있게 이해해봐요!

생성 패턴이란?

생성 패턴은 객체를 어떻게 만들지에 대한 똑똑한 방법입니다. 프로그램에서 객체를 그냥 마구 만들면 나중에 코드를 고치기 어려워요. 생성 패턴을 사용하면 객체를 만드는 과정을 잘 정리해서, 코드를 깔끔하고 유지보수하기 쉽게 만들 수 있어요!

Factory Method 패턴

무엇인가요?

Factory Method 패턴은 공장(Factory)이 물건을 만들듯이, 객체를 만드는 전담 메서드를 두는 패턴입니다. 우리가 직접 객체를 만들지 않고, 공장에게 "이거 하나 만들어줘!"라고 부탁하면 공장이 알아서 만들어줍니다.

실생활 비유

케이크 가게를 생각해보세요. 생일 케이크가 필요할 때, 직접 밀가루와 설탕을 사서 만들 수도 있지만, 케이크 가게에 주문하면 편리하죠? 가게는 케이크 만드는 방법을 알고 있고, 우리는 그냥 주문만 하면 됩니다. 새로운 맛의 케이크가 나와도 가게만 레시피를 업데이트하면 되고, 손님은 똑같이 주문하면 돼요!

왜 사용할까요?

  • 코드를 한 곳에서 관리: 객체 만드는 코드가 여기저기 흩어지지 않아요
  • 쉬운 수정: 객체 생성 방식이 바뀌어도 공장만 고치면 돼요
  • 새로운 종류 추가가 쉬움: 새로운 장난감이 추가되어도 간단해요

인터랙티브 데모: 장난감 공장

버튼을 눌러서 장난감 공장에 주문해보세요!

아직 만들어진 장난감이 없어요. 위 버튼을 눌러서 주문해보세요!

설명: 버튼을 누르면 ToyFactory.create_toy() 메서드가 실행되어 해당 장난감 객체를 만들어냅니다. 우리는 장난감이 어떻게 만들어지는지 몰라도 되고, 그냥 공장에 주문하기만 하면 돼요!
# 파이썬 코드 예제 class ToyFactory: def create_toy(self, toy_type): # 요청된 종류에 따라 알맞은 장난감 생성 if toy_type == "car": return CarToy() elif toy_type == "doll": return DollToy() # 사용 예시 factory = ToyFactory() toy1 = factory.create_toy("car") # 자동차 생성! toy2 = factory.create_toy("doll") # 인형 생성!

Singleton 패턴

무엇인가요?

Singleton 패턴은 오직 하나의 객체만 만들도록 보장하는 패턴입니다. 여러 번 만들려고 해도 항상 같은 객체를 돌려받아요. 프로그램 전체에서 하나의 객체를 공유해서 사용합니다.

실생활 비유

태양을 생각해보세요. 하늘에는 태양이 하나만 있죠? 지구상의 모든 생물이 그 하나의 태양을 공유합니다. 또는 학교의 교장선생님처럼, 한 학교에 교장선생님은 한 분만 계십니다. 여러 명이 있으면 지시가 엇갈려서 혼란스러울 거예요. Singleton도 이처럼 딱 하나만 있어야 하는 것을 표현할 때 사용해요!

왜 사용할까요?

  • 일관성 유지: 모두가 같은 객체를 보니까 데이터가 일치해요
  • 자원 절약: 매번 새로 만들지 않으니 메모리를 아껴요
  • 충돌 방지: 설정 관리자가 여러 개면 설정이 꼬일 수 있어요

인터랙티브 데모: 태양은 하나!

버튼을 여러 번 눌러서 태양을 만들어보세요. 몇 번을 눌러도 태양은 하나만 있어요!

버튼을 눌러 태양을 만들어보세요!

생성 시도: 0번
설명: 버튼을 여러 번 눌러도 태양은 하나만 생성됩니다. 이것이 Singleton 패턴의 핵심이에요! Sun()을 몇 번을 호출해도 항상 같은 객체를 반환합니다.
# 파이썬 코드 예제 class Sun: _instance = None # 유일한 인스턴스를 저장 def __new__(cls): if cls._instance is None: cls._instance = super(Sun, cls).__new__(cls) return cls._instance # 사용 예시 sun1 = Sun() sun2 = Sun() print(sun1 is sun2) # True - 같은 객체!

두 패턴 비교하기

Factory Method와 Singleton은 둘 다 생성 패턴이지만, 해결하는 문제가 달라요!

구분 Factory Method 패턴 Singleton 패턴
주요 목적 객체를 어떻게 만들지 객체를 몇 개 만들지 (하나만!)
초점 생성 방식의 유연성 유일한 인스턴스 보장
사용 상황 여러 종류의 객체를 만들 때 하나만 있어야 하는 객체
예시 장난감 공장, 케이크 가게 태양, 교장선생님, 설정 관리자
장점 확장 쉬움, 코드 중앙관리 일관성 유지, 자원 절약
객체 개수 여러 개 생성 가능 항상 하나만

핵심 정리

  • 공통점: 둘 다 객체 생성을 다루는 패턴이고, 코드를 깔끔하게 만들어요
  • Factory Method: "공장에서 주문해!" - 다양한 객체를 체계적으로 만들기
  • Singleton: "하나만 있어!" - 전역적으로 유일한 객체 보장
  • 함께 사용: 두 패턴은 서로 대체되는 게 아니라, 상황에 따라 함께 사용할 수도 있어요!

더 알아보기

언제 사용하면 좋을까요?

Factory Method를 사용하세요:

  • 비슷한 종류의 객체를 여러 개 만들어야 할 때
  • 객체 생성 로직이 복잡하거나 자주 바뀔 때
  • 새로운 타입을 추가하기 쉽게 만들고 싶을 때

Singleton을 사용하세요:

  • 설정 관리, 로그 기록처럼 하나만 있어야 하는 것
  • 여러 곳에서 같은 데이터를 공유해야 할 때
  • 자원을 아끼고 싶을 때 (데이터베이스 연결 등)
